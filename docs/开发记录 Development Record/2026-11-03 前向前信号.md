# 2026-11-03 前向前信号

协议名 `preforward-signal-r2-v1`。这一节在测量之前写定。上一轮 bonus 对齐的在线 K 对 ESP 只是弱的同向优势，对角 K 对 bonus 残差的 \(R^2\) 只有 0.01–0.03。家里 PC 的 `cursor/extra-branch-fair-20261103` 继续做额外分支的同预算对照。这次不改那条分支，不加节点，不重调 boost，也不改树怎么取 token。

## 要回答的问题

k=1、`branches` [4] 时，槽 0 的修正必须在前向之前写好。bonus 嵌入要等这轮验证提交完才知道。所以候选信号必须在 `masks()` 时已经在手，目标是这轮最后提交 token 的残差 \(e=y-m\)。\(m\) 是当时的 ESP 槽 0。

按这个时序排序，只留四个向量：

| **顺序** | **信号** | **前向之前为什么已经有** |
| --- | --- | --- |
| 对照 | \(z-m\)，上一枚提交嵌入 | 旧对角 K 用的就是它 |
| 1 | 上一轮 mask logits 的全词表期望嵌入减 \(m\) | 这批 logits 已经用来建了本轮的树，期望嵌入是草稿对下一位置的分布摘要 |
| 2 | 上一轮 mask 位置的最终归一化 hidden | 同一次前向的 final norm 输出，在 softmax 之前 |
| 3 | 上一轮 mask logits 在 top-4 上重新归一化的期望嵌入减 \(m\) | 4 等于 `branches` [4]，是树实际能起草的质量 |

熵、top-4 概率质量和上一轮接受长度是标量。它们单独进不了嵌入空间的线性映射，只作描述，不进门。当前轮的接受长度在前向之后才知道，只用来事后分层，不进拟合。

hidden 用原向量。三个嵌入信号都减去 \(m\)。低秩映射是 \(e \approx (xV)U^\top+b\)，岭罚 \(U,V\)，不罚 \(b\)。秩只比较 4 和 16。ridge 用既有网格 \(10^{-4}\) 到 \(10^{4}\)，在拟合 prompt 上做 5 折，种子 0。平局取更大的 ridge；两个秩的交叉验证误差再平，取秩 4。评测句不参加选择。

中心化 \(R^2\) 用拟合集的残差均值当中心，分子分母都用这个中心。预测等于拟合均值时，留出 \(R^2\) 接近 0。

## 预注册的门

拟合是 288 句式的前 128 条，每条 24 token。留出是 SpecBench `question_id` 81–208 的第一轮，128 条，每条 64 token，`stop_on_eos` false。本地 `question.jsonl` 只有 81–560。209–560 本轮不用：209–336 和 465–560 已经测过，337–464 留给家里的额外分支。81–208 在 2026-11-02 以 16 token 跑过混合增益。那段旧接受数不参与判据，也不用来选信号、秩或 ridge。第二轮文本会指代没放进 prompt 的上一轮回答，不用。句式下标 128–287 曾经评测过，也不用。

树是 k=1、`branches` [4]、T=0。采集臂就是 ESP，槽 0 不改。argmax 审计必须通过。权重只用本机缓存，CUDA，不下载。先跑 0.6B。

对角 \(K\) 对 \(z-m\) 和期望嵌入各报一个留出 \(R^2\)，不进门。低秩门只用交叉验证选中的那一个秩。

信号按期望嵌入、hidden、top-4 的顺序看。第一个同时满足下面两条的，记为可接入：

- 留出中心化 \(R^2 \ge 0.10\)
- 比 \(z-m\) 的低秩留出 \(R^2\) 至少高 0.05

一个都不满足，就不做 Kalman，也不跑 4B。满足之后，下一步才是把选中的映射冻成槽 0 修正，仍对 ESP、仍是四条分支。那一步另写预注册。在线更新要等冻结臂在 0.6B 上胜多于负再考虑。boost 保持 64，不在这批评测句上重选。

标量与 bonus 残差范数、接受数的 Pearson，以及接受长度为 0 和大于 0 两层的留出 \(R^2\)，只描述信号在拒绝轮和接受轮上是否一样，不改门。

测量脚本是 `studies/trajectory_observation/structure/preforward_signal.py`。日志、配对张量和拟合权重写到仓库外的临时目录，不进 Git。

## 测量

代码是 `fd512c2`。运行时工作区干净。只跑了 0.6B，本机缓存，BF16，`cuda:0`，没有下载。机器是 NVIDIA GeForce RTX 5090 D v2。采集约 4.5 分钟，退出码 0。argmax 审计失败会在脚本里停，这次没有停。校准 1867 行，和上一轮 0.6B 的 ESP 采集行数相同。SpecBench 81–208 有 5451 轮，其中 52.1% 接受长度为 0，52.1% 的 bonus 嵌入等于本轮第一个提交嵌入。解码提交 8064、解码调用 5451，ESP 的 τ 是 1.479。没有第二臂，所以没有配对胜负。

## 结论

门没有开。期望嵌入、hidden、top-4 的留出 \(R^2\) 都是负的，没有一个达到 0.10，也没有比 \(z-m\) 高出 0.05。拟合 \(R^2\) 有 0.26–0.40，留出为负，低秩映射记的是句式里的方向，换到 SpecBench 就比预测均值更差。对角映射还能留住大约 0.01，和上一轮 0.01–0.03 同一量级。接受长度为 0 的那一半轮次也是负的，所以不是“只在接受轮上才没有共享方差”。

按预注册，不接 Kalman，不跑 4B，不改 64，不加节点。标量相关也没有大到要改这条门。同预算下，前向之前能拿到的这几个线性信号解释不了 bonus 残差。下一步如果还要动槽 0，需要换掉“用句式拟合一个线性 \(K\)”这个形式；多一个节点的额外分支不在本轮里做。

# 输入轨迹状态实现

本批将 EMA → Holt → 轨迹 Kalman 的输入路线变成可装配代码。目标是先保证状态、树距离与提交时序正确；算法在真实大模型上的验收收益仍待实验。

## 算法与代码职责

新增 [trajectory.py](../../src/spec_mtp/structure/algorithm/mask/trajectory.py)，由现有 [factory.py](../../src/spec_mtp/structure/algorithm/mask/factory.py) 注册 `method: input_trajectory`。五种 `kind` 共享 prompt 均值初始化、V=0 与最后 prompt token 的位移观测起点，避免将历史 EMA 的 prompt 速度热启动混入更新公式比较。历史 provider 保持原样。

令 y 为本次正式提交 embedding，α 为新位置权重，β 为旧速度保留权重：

| 模式 | 提交后的更新 | 读出 |
| --- | --- | --- |
| `order0` | M ← M+α(y−M)，V=0 | M |
| `difference` | M 同零阶；V ← βV+(1−β)(y−y_prev) | M+hV；显式 `anchor: last` 时用 y+hV |
| `holt` | r=y−(M+V)；M ← M+V+αr；V ← V+α(1−β)r | M+hV |
| `kalman` | F=[[1,1],[0,1]]，H=[1,0]；预测、Riccati 增益、残差修正与 Joseph 协方差更新 | M+hV |
| `fixed_gain` | 同一 Q/R 实际求解收敛后的 G∞ 固定修正 M/V | M+hV |

α=1 的 Holt 与差分 EMA 只有在初始 M=y_prev、初始 V 和后续观测均一致时才对应。默认 prompt 均值不总等于最后观测，因此不能无条件宣称等价。

M/V 为 float32，协方差为 CPU float64 的共享 2×2 矩阵，不为每个 embedding 分量拟合独立协方差。固定 Q/R 的增益取决于协方差与提交步数，不随残差幅度自适应；冻结增益若未收敛则报错。该模型不等于旧的标量 Kalman、仿射 K 回归或完整联合 hidden 观测算法。

P/Q/R 使用同一正尺度下的归一化系数。公共尺度在 G 中约掉，本版不从 prompt 方差或 fit 残差猜测真实噪声，也不输出物理单位的 P。若需要解释绝对不确定性，后续另做 fit；不把未使用的尺度估计挂在策略上。

## 时序与验收计数

`masks()` 预测 prefill 槽位；`masks_for_tree(tree)` 对 root 和全部 owner 纯读，默认 h=depth+一基 slot。相同深度的兄弟使用相同状态预测，draft ID 不吸收进 M/V/P。`horizon: slot` 单独控制旧布局距离，不重新启用历史热启动。

已有 decoder 在 EOS／长度裁剪后逐 token 提交，包括 bonus，新增策略只在这些调用中更新。重复读取、拒绝分支和被截掉的尾部不更新。没有新增 decoder、通用 runner 或输出 hidden 伪观测。

[loop.py](../../src/spec_mtp/structure/algorithm/decode/loop.py) 追加 `retained_accepted`、逐轮 `retained_accepted_nodes` 与 `acceptance_metrics` 协议：A 是最终保留 draft，C 是 decode 调用，S 是 decode 提交（含 bonus、不含 prefill 首 token），A/C 与 τ=S/C 在 C=0 时为 null。计数随每个实际提交递增，块内失败也保留已提交事实。旧 `accepted`、attempt/accept_by_depth 和旧汇总行为不改，不能拿来冒充 A。

[audit.py](../../src/spec_mtp/audit.py) 对新协议检查完整字段、路径前缀、整数类型与比值一致；旧记录缺少新字段时保持旧合同，不补算后回签。输出／采样验证规则未在此改变。

## 验证与后续

测试镜像位于 `tests/spec_mtp/structure/algorithm/mask/` 与 `decode/`；覆盖手算增益、Holt 残差、退化等价的条件、树 position ID、预测纯读、P 的对称半正定、稳态收敛失败、残差幅度不改变固定 Q/R 增益，以及正常／拒绝／EOS／预算／部分失败的提交时序。极小随机 Transformer 另做静态／动态树 T0 与 CPU AR 诊断。

最终有界 CPU 门禁1184项通过，无失败或跳过；Ruff 和修改的 audit.py mypy 检查通过。验证结束于11月21日凌晨，源码字节与冻结候选一致，完整回执见下文运行记录。该结果只支持工程合同，不构成真实模型研究收益。

完整 CPU 门禁首次因基线缺失39项 manifest 元数据而未收集执行，本批只补其声明，不改旧断言或放宽门禁。历史 Git 取证遇到 Windows 工作树所有权限制时，使用进程级 `safe.directory`，不改全局配置。实际命令、结果、失败尝试与来源摘要见[运行记录](<../运行记录 Run Record/2026-11-20 输入轨迹CPU验证.md>)。

# 2026-11-03 同节点额外分支

协议名 `extra-branch-replace-v1`。这一节在测量之前写定。2026年11月2日的额外分支（`a90ecc2` 所记的那次，输出在 `D:\GitHub\DreamSoul\output\dsd-opened-branch-20261102`）在 SpecBench 209–336、每条 64 token 上超过了 ESP：4B 35 胜 11 负，0.6B 38 胜 10 负。那次树是 `branches` [4]，修正 token 作为额外的深度 1 节点加进去。多出来的节点和候选内容绑在同一次比较里。

这次把候选换进原有预算。ESP 与替换臂都是 k=1、`branches` [4]、剪枝开、T=0。替换臂的槽 0 保持 ESP mask，K 冻结在校准值上。修正嵌入的 top-1 若还不是深度 1 子节点、也不是根 token，就替换累计概率最低的无子节点深度 1 叶；并列时替换更靠后的叶。节点数不变。实现若发现节点数变了，这次运行中止，不能把结果记成通过。已经存在的 token 不替换。ESP 不改成五条分支：修正 token 已经在前四名时，五条分支的 ESP 会比替换臂多一个节点。修正嵌入的那一次单 token 前向保留，它不属于节点预算。

校准沿用 11 月 2 日的做法。288 句式的前 128 条，每条自回归 24 个 token，在不乘 K 的 ESP 轨迹上取 \((\hat m, z, y)\)，对角最小二乘，\(Q=0.01P\)。评测集不参与拟合。4B 用 `D:\models\Qwen3-4B`，0.6B 用 `D:\models\Qwen3-0.6B`。两份都是本机缓存，BF16，CUDA，eager。分词是 `tokenizer(text)`，不用 chat template，与那次额外分支一致。

主评测是 SpecBench `question_id` 337–464 的第一轮原文，128 条，不包含 81–336，因此不包含 209–336。每条 64 token，`stop_on_eos` false。跨数据集复验是 Dolly `databricks/databricks-dolly-15k` 的 `creative_writing`，train split 迭代顺序上的前 128 条非空文本。K 不在 Dolly 上重估。两个数据集分开判定。

主比较是替换臂对 ESP。逐 prompt 接受数，双侧符号检验，p<0.05 且胜多于负。4B 与 0.6B 都要通过，该数据集上的同预算主张才算通过。τ 的 prompt 均值和合计值都只报告。独立 AR 不一致只诊断。argmax 自检必须通过。未通过就不加宽树、不改 K、不加 prompt。

## 和两条旧路线的差别

`output_hidden` 原版没有 K。它在 FP32 里用已提交 token 的最终归一化 hidden 更新 anchor 和 velocity（β、β′ 两个 EMA），再用块内 proxy hidden 往前滚，最后按嵌入表平均范数把方向缩放成 mask。

嵌入空间的混合增益是 \(m=\hat m+K(z-\hat m)\)，\(\hat m\) 是 ESP 槽 0，z 是上一枚 token 的输入嵌入。校准 K 在 4B 上约 −0.06、0.6B 上约 −0.07，和当前残差没有正的对齐。2944 行先验把在线权重压到约 \(4\times10^{-4}\)。修正先落到 bf16 上，增量和舍入是同一量级。同一条修正 mask 发给所有 owner，K 却只在 root 上更新。

这次状态改成输出 hidden 的轨迹。观测改成已提交 token 的真实输出 hidden，以及块内 proxy hidden。K 仍是逐维，离线校准作初值，每条 prompt 再在线更新。mask 在 FP32 里乘完 K、做完范数缩放之后才转成模型 dtype。

## 公式

记已提交轨迹的 anchor 为 \(a\)、velocity 为 \(v\)。块内用局部副本，不写回已提交状态。owner 0 的观测 \(z_0=a\)。之后每个 owner 先记下当前 anchor，再吃进对应的 proxy；最后一个 owner 没有新的 proxy，只做 \(a\leftarrow a+v\)。槽是

\[
\hat h_{d,j}=a_d+j v_d.
\]

修正只发生在 hidden 上，而且在除以范数之前：

\[
h_{d,j}=\hat h_{d,j}+K\odot(z_d-\hat h_{d,j}).
\]

mask 是 \(s\cdot h/\|h\|\)，\(s\) 是嵌入表的平均范数。`trajectory` 和 `collect` 不乘 K，发出的 mask 与 `output_hidden` 原版相同。`collect` 只为了记下校准行。

根上的目标 y 是这次修正所预测的那个已提交 token 的输出 hidden。拒绝时它要到下一轮的 root hidden 才出现，所以更新晚一轮。接受时第一个草稿节点的 hidden 就是这个目标，当场更新。更深 owner 的误差用同一套目标规则记下，但不更新 K。k=1 时，接受一轮只把 owner 1 的目标推迟到下一轮 root。

在线更新和嵌入空间混合增益同一套对角式，用的是发出修正时的 K，不是更新瞬间又变过的 K：

```text
x <- z - h_hat          # root slot 0
innov <- (y - h_hat) - K x
P_minus <- P + Q
g <- P_minus x / (R + P_minus x^2)
weight <- g x
K <- K + g innov
P <- (1 - g x)^2 P_minus + g^2 R
```

`hybrid` 每条 prompt 把校准得到的 P 和 Q 乘 boost。boost 固定为 64，等于评测生成长度，不在评测集上选。R 和 K 的初值不乘。`frozen` 不更新。`scratch` 从 K=0、P=R=1、Q=0.01 开始，更新式相同。

校准仍是

```text
x <- z - h_hat
e <- y - h_hat
K <- sum(e x) / sum(x^2)
R <- mean (e - K x)^2
P <- R / sum(x^2)
Q <- 0.01 P
```

行来自 `collect`，也就是不乘 K 的 output hidden 轨迹。4B 和 0.6B 分开校准。

范数缩放会消掉纯径向的修正。K 要改变 hidden 的方向，mask 才会变。这是 output hidden 映射本身的约束，不是再把修正加到 bf16 上。

## 预注册的测量

主比较是 hybrid 对 ESP，以及 hybrid 对 output hidden 原版。两条都要逐 prompt 接受数、双侧符号检验、p<0.05 且胜多于负。冻结 K、从零在线、trajectory 各自对 ESP 和原版报告，不另设通过线。trajectory 对原版应当全平。

校准是 288 条模板句的前 128 条，每条 24 token。主评测是 SpecBench `question_id` 209–336，128 条，每条 64 token，`stop_on_eos` false。这 128 条和校准句不重合，数据集也不同。另一组是模板句下标 128–159（第 129–160 条），32 条，每条 64 token，紧接在前 128 条校准之后，不重合。树是 k=1、`branches` [4]、T=0。4B 为主，0.6B 用同一批 prompt 作对照。只用本机已有权重，不下载。

root 和 deep 的修正误差分开累计：修正后的槽 0 对目标 hidden 的均方，以及不乘 K 的均方。

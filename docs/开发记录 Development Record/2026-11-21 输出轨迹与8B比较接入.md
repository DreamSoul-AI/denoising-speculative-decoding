# 输出轨迹与8B比较接入

用户要求实现8B output路线，并与input的EMA、Holt、Kalman比较接受量和τ。新`output_trajectory`组合既有零阶／差分／Holt／Kalman递推，观测为已提交位置的真实final-normalized hidden，初始化为prompt hidden均值和零速度。input策略保持原数学。

Qwen3-8B实际输入和输出权重不绑定，不能继续使用旧output_hidden的同空间假设。新读出固定为：预测hidden归一到本prompt真实hidden平均范数，经实际输出头softmax（温度1）后乘输入embedding表，得到输入空间期望embedding。所有输出状态共用它，不在eval调尺度、不拟合Jason校准。两路线的观测时点与读出不同，因此结论是可部署方案比较，不是纯表示单因素归因。

令最后真实hidden观测位置为p，root位置r，owner深度d，一基slot为i；mask位置q=r+d+i，所需预测hidden位置为q−1，外推距离为q−1−p。decoder只提交root和最终保留draft的真实hidden；bonus通常没有在本次forward出现，到下一轮root才取得。EOS／预算停止轮仍记下实际可取得的已提交hidden，拒绝分支与未保留尾部不进入状态。账本保存位置、forward及当前不可得bonus位置；只prefill的生成也保存初始化账本。

`output_trajectory.py`负责状态组合与读出，`loop.py`复用同一解码器并为新策略添加位置回调。旧output_hidden及其proxy行为不改。factory与科学CLI只对新方法传入真实头。HF加载适配支持显式device_map，让8B直接载入GPU，避免先在CPU完整复制；默认加载方式保持原义。

13项输出针对性参数检查通过，包含untied tiny Transformer的T0和CPU AR诊断、纯读、真实头映射、位置连续性及长度1／2／9。与既有Study／CLI的组合检查43项通过。完整CPU回归及真实8B条件以运行记录为准，不能将这些CPU检查当接受量收益。

Study复用已有有界实验入口，新增固定两路线×四状态的配置和配对分析。参数来自先前4B开发，8B不再次搜索；新数据先留eval再抽dev，源码、数据、权重和计划冻结在共享artifacts。初次先导被会话中断，保留部分raw；恢复先导另开目录，16次／256输出token全部审计通过。没有覆盖旧Run或回签其终态。

最终完整CPU门禁1206项通过，无失败或跳过；正式8B共320次／20,280输出token全部重审计，160条output位置账本独立复核通过。本版output整体低于input，output Kalman对自身零阶有正向差异，详见[研究记录](<../研究记录 Research Record/2026-11-21 8B输入输出路线比较.md>)与[运行记录](<../运行记录 Run Record/2026-11-21 8B输入输出状态比较.md>)。结论不替代对读出、P0及冻结增益的后续隔离。

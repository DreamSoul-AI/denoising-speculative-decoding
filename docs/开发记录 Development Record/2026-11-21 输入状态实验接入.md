# 输入状态实验接入

用户在输入状态实现完成后要求执行实验。本批为已有 decoder 添加固定 E1 协议薄入口，不修改五种输入策略或验证规则。实验设计与判读以[研究计划](<../研究计划 Research Plan 去噪推测解码.md>)为准，实际执行见[运行记录](<../运行记录 Run Record/2026-11-21 输入状态E1实验.md>)。

`studies/trajectory_observation/structure/input_state.py` 负责八类去重与旧文本排除、先留 eval 再抽 dev、模板显式编码、23候选配置、dev τ 选择、冻结增益对照及冻结六臂 eval。`flow/input_state.py` 只读冻结配置并转调。模型按阶段核验完整成员，不为每条短输入反复重读全部权重；每条 raw 仍记录模型声明与真实会话，完成 summary 前再次核对来源，漂移或 T0 失败保留部分证据且不宣布完成。

`structure/input_state_analysis.py` 仅分析已完成 Run：逐条重新审计 raw，核对行级 A/C/S、输出和完整 eval 配对，再汇总新协议、分类表、合计 τ 的配对 bootstrap、输出／长度差异，导出 JSON/CSV/Markdown。`flow/analyze_input_state.py` 是薄入口。它不加载模型，不修改旧 Run，不用旧 `accepted` 冒充最终保留 A。

初次先导暴露 tokenizer 返回类型变化，修复为模板渲染后明确编码；原失败来源保留，重新冻结后重跑。针对性测试覆盖该行为，并以随机 tiny Transformer 的真实 raw 检查分析成功与篡改拒绝。测试均登记到现有 manifest。完整 CPU 回执在运行记录维护；运行中的生成快照保持不变，新增离线分析单独留源。

不修改 CI、第三方来源或模型权重；不合并 Draft PR。输出 hidden 的观测位置账本仍是后续工程项，本批实验结果不能替代它。

最终完整CPU计划1190项通过，Ruff通过。0.6B先导与4B开发／冻结留出完成，离线重审计384条4B raw。差分与Holt增量尚不稳定，动态Kalman未优于冻结增益；下一步初始化控制见[研究记录](<../研究记录 Research Record/2026-11-21 输入状态首轮比较.md>)。

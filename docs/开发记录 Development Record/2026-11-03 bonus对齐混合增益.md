# 2026-11-03 bonus 对齐的混合增益

协议名 `hybrid-gain-bonus-aligned-v1`。这一节在实现和测量之前写定。家里 PC 的 `cursor/extra-branch-fair-20261103` 继续做额外分支的同预算对照、跨数据集复验、输出 hidden 负结果消融和 `src/rpipe` 清理。这次不重复那些，也不改那条分支。

## 观测差在哪

k=1、`branches` [4] 时，块里每个 owner 共用同一条 mask。根上的 mask 占着本轮第一个新 token 的位置。最深接受节点上的 mask 占着 bonus 的位置，也就是本轮最后提交的那个 token。下一棵树的草稿分布取自这后一条 mask 的 logits。拒绝时第一个和最后一个是同一个 token，两条位置重合。接受时它们不是同一个 token，下一棵树看的是 bonus 那一位。

`hybrid-gain-kalman-v1` 的在线更新在 `on_token_committed` 的第一次调用上把 K 拟合到本轮第一个提交 token，随后的提交只刷新 z。校准也按这个 y 收集。发出的修正是 \(m=\hat m+K(z-\hat m)\)，z 是上一枚 token。mask 要代表的是 bonus，y 却是第一个 token。接受轮上，K 被推向草稿 token，而真正决定下一棵树的那条 mask 站在 bonus 上。

## 公式

默认 `observe=first` 保持旧协议，旧测试和旧结果仍按第一次提交更新。`observe=last` 才是本协议。`collect` 不乘 K，同一轮同时记下两个 y。

```text
each masks(), before the forward:
    m_hat <- ESP slot 0
    z <- last committed input embedding, if one exists
    emit slot 0 <- m_hat + K (z - m_hat)
    remember (m_hat, z, K)
each commit in the round:
    refresh z
    ESP mean updates on every commit
at the end of the round, y <- the last committed embedding:
    x <- remembered z - remembered m_hat
    innov <- (y - remembered m_hat) - K x
    P_minus <- P + Q
    g <- P_minus x / (R + P_minus x^2)
    K <- K + g innov
    P <- (1 - g x)^2 P_minus + g^2 R
```

`opened` 每条 prompt 把校准 P 和 Q 乘 64，K 和 R 不乘。64 等于评测生成长度。`frozen` 只用校准 K，不更新。旧观测对照是 `observe=first` 的 `opened`，它的 K 用第一个提交 token 校准，更新也用第一个。两条在线臂的 boost 相同。修正写进槽 0。没有第二次前向，树仍是四条分支，节点预算与 ESP 相同。

校准：

```text
x <- z - m_hat
e <- y - m_hat
K <- sum(e x) / sum(x^2)
R <- mean (e - K x)^2
P <- R / sum(x^2)
Q <- 0.01 P
```

y 分别取第一个和最后一个提交 token，得到两套先验。行来自 `collect`，也就是不乘 K 的 ESP。4B 和 0.6B 分开。同时记下有多少轮两个 y 不同，以及两个残差的余弦。这些数只描述错位有多大，不用来改 K、改 boost 或改评测句。

## 预注册的测量

主比较是 `opened` 且 `observe=last` 对 ESP。逐 prompt 接受数，双侧符号检验，报告胜、负、平、p 和 τ。τ 是解码提交数除以解码调用数。两个模型都是胜多于负，记为方向正向，即便其中一台的 p 不低于 0.05。两个模型都是负多于胜，记为这条对齐没有超过 ESP。方向分裂则不把对齐写成补上了缺口。

`frozen` 且 `observe=last`，以及 `opened` 且 `observe=first`，各自对 ESP 报告，不另设通过线。对齐在线臂相对旧观测在线臂也要两个模型同向更好，才把差异归到“y 从第一个改成 bonus”。

校准是 288 条模板句的前 128 条，每条 24 token。评测是 SpecBench `question_id` 465–560，96 条，每条 64 token，`stop_on_eos` false。不使用 81–336，也不使用 337–464。树是 k=1、`branches` [4]、T=0。4B 与 0.6B 都跑。权重只用本机缓存：4B 为 `D:\models\Qwen3-4B`，0.6B 为 `studies/input_mask_baseline/shared/model/modelscope/Qwen/Qwen3-0.6B`。不下载。argmax 审计必须通过。未通过则不改 64，不加节点，也不按结果重选评测句。

测量脚本是 `studies/trajectory_observation/structure/bonus_aligned_gain.py`。日志和配对张量写到仓库外的临时目录，不进 Git。

## 测量

代码是 `ddf23d1`。运行时工作区干净。4B 与 0.6B 都是本机缓存，BF16，`cuda:0`，没有下载。机器是 NVIDIA GeForce RTX 5090 D v2，torch 2.11.0+cu130。校准行数 4B 为 2297，0.6B 为 1867。两个 y 不同的轮次 4B 为 647，0.6B 为 1077。这些轮上两个残差的余弦是 4B 0.031、0.6B 0.0045。校准 K 均值：4B 的第一个和最后一个都是 −0.110；0.6B 第一个 −0.113，最后一个 −0.063。在线权重均值约 0.022（4B）和 0.025（0.6B）。argmax 审计全部通过。独立 AR 没有另跑。

τ 是解码提交数除以解码调用数。胜负是逐 prompt 接受数，平局不进符号检验。

SpecBench 465–560，96 条，64 token。

| **臂** | **4B τ** | **4B 对 ESP** | **0.6B τ** | **0.6B 对 ESP** |
| --- | --- | --- | --- | --- |
| ESP | 1.423 | — | 1.503 | — |
| 冻结，y 为 bonus | 1.438 | 44:33:19，p=0.254 | 1.510 | 36:35:25，p=1.0 |
| 在线，y 为 bonus（主方案） | 1.428 | 44:37:15，p=0.505 | 1.515 | 38:29:29，p=0.328 |

看完接受数之后，用已经写下的校准行补了一项描述，没有改臂、没有重跑。对角 K 对残差的 \(R^2\)：4B 上第一个目标 0.035、bonus 目标 0.031；0.6B 上 0.031 和 0.012。只在两个 y 不同的轮上，用草稿 token 的残差去拟合 bonus 的残差，\(R^2\) 是 4B 0.016、0.6B 0.029。

## 结论

按预注册的方向规则，主方案对 ESP 是正向：4B 44 胜 37 负，0.6B 38 胜 29 负。两边 p 都高于 0.05，τ 只从 1.423 到 1.428、从 1.503 到 1.515。这不是稳定拉开的优势。

收益不能归到观测对齐。0.6B 上旧观测是 22:52，对齐把它从明显更差拉回 ESP 上方，相对旧观测是 57:19。4B 上旧观测对 ESP 是 53:32（p=0.029），对齐后的在线臂反而比它少赢（25:38）。4B 两个目标的校准 K 都是 −0.110，因为多数轮两个 y 相同。冻结的 bonus 先验在 4B 上 τ 最高（1.438，44:33），在线更新没有再抬高它。

对角 K 解释不了 bonus。残差 \(R^2\) 只有 1% 到 3%，接受轮上草稿残差和 bonus 残差近乎正交。所以不再把“换一个 token 当 y”或“按 owner 换成草稿嵌入再乘同一个对角 K”写成下一条。bonus 是在消费 mask 的同一次前向里才知道的；同预算下，用上一枚嵌入的对角修正替不了它。先前真正拉开的是多一个节点的额外分支，同预算对照仍由家里的 `cursor/extra-branch-fair-20261103` 做。不改 64，不加节点，也不按 4B 上旧观测的 53:32 把主比较改掉。

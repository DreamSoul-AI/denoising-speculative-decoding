# 输入状态 E1 实验

本批检验输入 embedding 的趋势更新与协方差增益能否提高真实接受量。用户在输入开发完成后授权运行实验；执行协议先登记于[研究计划](<../研究计划 Research Plan 去噪推测解码.md>)。源码基线为 `2c74821fde1186f81eecae9234e9e4534372d84e`，实验接入是其上新增、冻结的工作树代码，不冒充已提交版本。

Windows、Python 3.13.9、torch 2.11.0+cu130、Transformers 5.12.1，复用已有 Qwen3-0.6B／4B，RTX 5090 D v2，BF16/eager、thinking=false、最多512输入 token、单 mask、branches=[14]、BC30、贪心。没有下载、安装或修改共享 Python 环境。

外部 Run 根为 `D:\360安全浏览器下载\Agent\DreamSoul\tmp\输入状态E1 20261121 0022`。`source-v2/`、`source_manifest-v2.json` 冻结697项生成源码／测试／配置，模型全部成员 SHA256 分别在 `model-06.json`、`model-4b.json`，数据、版本与排除数在 `dataset.json`。离线分析单独冻结于 `analysis-source/`、`analysis_source-v2.json`，没有替换生成进程的冻结来源。运行脚本入口为 `studies.trajectory_observation.flow.input_state`，配置为 `config-06-v2.json`／`config-4b-v2.json`。

HF Dolly 固定 revision `bdd27f4d94b9c1f951818a7da7fd7aeea5dbff1a`，复用此前核验的完整本地 JSONL，本轮重新记录字节哈希。递归排除旧来源实验输入中的400个已用文本；seed=20261128，去重后按八类先预留 eval32（每类4），再取 dev8（每类1）。实际原文、全局行号和输入 token ID 均落盘；只有一次抽样，不宣称三次校准重复。

启动时可用内存约16.51 GiB，4B 运行后约14.97 GiB；显卡总显存24,455 MiB，载模前占用约2.8 GiB，4B 生成时约11.1–11.4 GiB。进程枚举未显示有效条目，连本次进程也未列出，因此不能用空列表证明没有其他 GPU 作业。运行按可见显存与实际数值错误控制，结果不作墙钟测速判断。

## 先导与执行时序

初始 `pilot/` 在载模前因 Transformers tokenizer 返回 Encoding 对象、无法直接 JSON 序列化失败；原 `source/`、配置、失败与控制台保留，没有覆盖。修复为先 `apply_chat_template(tokenize=False)`，再 `encode(add_special_tokens=False)`，新增检查后重新冻结 v2。

`pilot-v2/` 使用0.6B，在两条 dev 上运行五种策略、各16生成 token，10次生成共160个输出 token，全部逐提交 T0 与来源声明审计通过。该连通检查不用于选择4B参数。

`main-v2/` 使用4B，先完成23候选×8条 dev，再用选定 Kalman 参数跑冻结增益的8条 dev。192条开发观测共11,664个实际输出 token。选择清单先于 eval 写入：差分 β=.9999，Holt α=.1/β=.99，Kalman qM=.01/qV=.0001、R=P0=1；冻结增益复用这组 Q/R。平分按预先声明的候选顺序处理，无 eval 回调选参。

六臂后续使用同一 eval32，逐 prompt 轮换臂顺序，所有额外 observation／Jason K 关闭。模型文件在模型阶段前、dev→eval 和结果终态核验；raw header 保存完整模型清单及实际模型信息。每条生成保留逐提交 raw、最终保留 A/C/S、输出 token 和 T0 verdict，失败不写完成 summary。最终结果由完成回执与离线重新审计确认，不以控制台出现数字判定完成。

## 验证与结果入口

抽样隔离、dev-only 选择／平分、BC固定、模板编码、配对重采样及真实 tiny-model raw 重审计的针对性检查已通过。最终完整 CPU 计划 `cpu-pr-2/` 为1190项通过、无失败或跳过、约297秒，Ruff通过。此前 `cpu-pr-1/` 的1189项通过覆盖当时已收集的5个 E1 用例，第6个集成用例加入后完整重跑，以1190项回执为准。原始记录均位于上述 Run 根，未提交模型、数据和 raw 到 Git。

本批只覆盖输入路线与一次小样本探索。输出 hidden 延迟账本、跨模型／跨数据集确认、采样分布和吞吐收益未覆盖。所有 τ 使用 decode 实际 S/C；N 含 prefill 首 token，A 不含 bonus 与截掉的尾部，历史 ESP 的 BF16 状态与新 float32 状态分列报告。

## 完成结果与重审计

0.6B先导和4B主运行均退出0，完成来源末尾核验后写入summary。4B共384次生成（dev192、eval192）、23,946个实际输出token；离线重新审计全部384条raw，核对来源声明、逐提交T0及行级A/C/S。加上先导，共394次生成、24,106个输出token，不计入失败的初始先导。0.6B／4B CUDA峰值已分配显存约1.14／7.82 GiB。

# 算法说明 Algorithm Description ESP

## 当前 input 接口与 BC 构树顺序

更新日期：2026年11月28日。当前只考虑 input，保留 ESP 的公共 block、树注意力、候选选择、验证与缓存处理。探测槽统一读取当前共享水平向量 M，不按槽或树深度额外读出 M+hV。只有探测向量的状态更新发生变化。

| **结构** | **固定增益** | **Kalman 增益** |
| --- | --- | --- |
| 零阶水平 | EMA，按原 ESP 规则对齐的基线 | 零阶 Kalman |
| 水平与趋势 | Holt | 水平—趋势 Kalman |

EMA 与 ESP 的水平递推在 prompt 均值初值、更新 token、顺序／时点和权重一致时对齐，本轮不重复列为两个独立算法臂。原 ESP 来源版本和数值状态仍记录，历史精度或调度差异不冒充算法收益。差分 EMA 若 V 不进入 M 更新或实际读出，对探测无作用，退出当前四臂；M+hV 的显式外推保留为后续另一项改动。

正式提交的 token 给出 input embedding z，依位置顺序更新一次。正常候选节点始终输入自己的 hard token embedding，附属槽输入 soft M。M 更新不重算旧 logits，不修改旧候选。额外 probe 融合、output、Jason 组合、树预算重分配和 Q/R 在线更新均不纳入当前比较。

### 预算先于候选分配

先固定 block 总位置预算 B、每个正常节点附属槽数 k，再得到候选容量 $N=\lfloor B/(1+k)\rfloor-1$，其中 root 也配 k 个槽。BC30、k=2 时：1 个 root＋9 个 hard 候选＋20 个 soft 槽＝30 个新增位置。缓存历史前缀不重复计入。

容量不是候选池大小。先从 probe 分布提出候选，按累计探测分数和 Top-1 深入扩展约束保留预算内连通树。各层留几个由评分及策略决定，7＋2 是附录例子，不是 BC30 固定层宽，也不保证全局真实概率最优子树。原树节点用 hard embedding 验证，附属 soft M 探测后续候选。[论文 §3.3—3.4](https://arxiv.org/html/2603.17942v2#S3.SS3) · [附录 D](https://arxiv.org/html/2603.17942v2#A4)

当前沿用选定基线的 k、BC 与层宽配置，不联合优化每节点槽数。历史单槽 BC30／branches=[14] 的实验与双槽教学例子分开。EMA 与 Holt 的详细更新见 [EMA 算法说明](<算法说明 Algorithm Description EMA与Holt.md>)，Kalman 与校准见 [卡尔曼算法说明](<算法说明 Algorithm Description Kalman.md>)。本文说明当前机制；历史候选和旧实验按日期记录定位，不改变本节的当前范围。

## 多层候选的来源与验证时序

2026年11月28日补充。候选在 verification 之前由 mask 输出提出；verification 只确认候选路径中能够接受的前缀，同时该次前向中的附属 mask 又为下一轮提供提案。不能把“最终保留了更长路径”写成“verify 凭空生成了所有深层候选”。

### 两个 mask 如何给出 A 与 X

以 prefill 为起点，已有正式前缀为 C，尾部附上两个槽，输入值可以相同：

$$[C,M_1,M_2],\qquad M_1=M_2=M.$$

一次前向后，C 的末位置输出下一个正式 token r；第一个槽输出词表分布 q1，提议 r 后面的 token；第二个槽输出词表分布 q2，提议再后一个 token。两个槽的输入 embedding 相同，位置和可见上下文不同，hidden 和输出分布可以不同。

第二个槽产生最终 hidden $h_2$，经过模型原有输出头即可得到：

$$q_2=\operatorname{softmax}(\operatorname{LMHead}(h_2)).$$

X 就是从这份分布取出的具体 token ID，例如其 Top-K 成员。这里“有 X 的概率”指存在 soft 探测分数 q2(X)，不代表已经获得在 hard A 条件下的真实分布：

这里 q2(X) 是 soft 上下文中的提案分数；目标验证分布则是 $p_\theta(X\mid C,r,A)$。两者的输入条件不同，不保证数值相同。

产生 q2 时，输入中还没有 r、A 这两个刚读出的 hard token；第二个槽通过因果注意力看前缀、第一个 soft 槽及自身位置。不能声称模型先读到 q1 的 argmax A，再在同一次前向把 A 喂给第二个槽。mask hidden 在层间变化，也不等于中途选出一个 hard ID 并重新输入。

### 怎样把不同位置的提案接成多层树

假设 q1 提出 A、B，A 是该深度的 Top-1，q2 提出 X、Y。当前仓库的 Top-1 扩展把 X、Y 接在 A 下面，构成 r→A→X 和 r→A→Y，同时保留 r→B 等浅层分支。这样构造的是待验证的组合，不需要先额外跑一次 hard A 才能提出 X。

不同槽的输出可能相关；以下乘积是构树评分规则，不是统计独立性结论。例如提案路径评分为：

$$s(A\to X)=q_1(A)q_2(X).$$

这是累计探测分数，不是 hard 路径的精确联合概率。节点保存父节点和深度；预算筛选需保持祖先闭包，保留 X 时必须保留它的父 A。九个候选指九个树节点，不指九个连续位置。BC30、k=2 可容纳九个候选节点，当前这套构树每次最多提出两层；k=1 时只提出一层。7+2 是层宽示例，不是固定分配。

### 下一次 forward 怎样验证 A→X

构树之后才把 r、A、X 等 hard token 的 embedding 连同各自附属槽放入下一次块前向，利用树 attention mask 隔开不兼容分支，position ID 按路径深度对齐。在贪心规则下：

1. r 的输出计算 $p_\theta(\cdot\mid C,r)$，其 argmax 与孩子 A 匹配才接受 A。
2. A 的输出计算 $p_\theta(\cdot\mid C,r,A)$，其 argmax 与孩子 X 匹配才继续接受 X。
3. 前面不匹配，后代即使有输出也不能越过父节点被接受。前向并行计算不改变验收沿路径顺序进行的条件。

这里才真正取得 hard A 条件下验证 X 的分布；它与先前 q2 的用途不同。其他目标解码规则需要相应验收合同，此处只示范当前主比较的贪心规则。

### 路径走到叶子后为什么仍能继续

若 A、X 都接受，X 的正常节点输出还能给出下一个正式 token b，即本轮 bonus。叶子 X 也有两个附属槽，这些槽在同一前向已经产生两份更远位置的探测分布。以 b 为下一轮新根，使用 X 附属槽的分布重新构树。因此可以用尽当前路径的候选，却不会因为候选用完而无法继续；EOS、生成上限等正常停止条件另行处理。若一个候选也未接受，则使用旧根附属槽的输出。

此时附属槽输出仍是在旧 soft 占位条件下产生的提案，不假装已经把新 bonus b 作为 hard 输入算过。下一轮 hard 路径验证负责纠正不匹配。状态 M 更新也不会回头重算这些已产生的分布；下一次实际填槽才使用新 M。

完整循环为“旧 mask 输出→本轮 hard 候选树→本轮块前向同时验证与探测→接受路径与 bonus→取接受终点的 mask 输出→下一轮树”。第一轮种子来自 prefill。

依据：[论文 §2—§3.4](https://arxiv.org/html/2603.17942v2#S3.SS3)。当前仓库实现定位到 `build_static_tree`／`build_dynamic_tree` 的按槽分布构树，以及 decode loop 中的 `accepted_nodes`、`n_star`、`mask_rows` 和下一轮 `mask_logits` 选择；这是本仓实现的核对结论，不称作者官方代码。会议中 00:47—00:50 提出的深层候选来源问题，由这里区分提案分布与 hard 条件验证分布来解释。

## 逐 token 更新与同轮共享 M

2026年11月28日补充：逐 token 递推与共享槽位。

这里的“正式提交”指 verification 后最终保留并接入生成序列的 token，包括按原 ESP 提交口径保留的修正／bonus；被拒绝、未走分支或被结束裁剪丢弃的 token 不更新状态。沿用 ESP 的更新事件与调度，不为每个探测槽新增更新事件。

设本轮前已有 t 个更新事件，本轮最终保留的 embedding 为 $z_{t+1},\ldots,z_{t+s}$。先用本轮实际填入的 M 完成前向与验证，再按 token 顺序执行 s 次完整状态递推，得到最终状态。下一次重新填充探测槽时，所有槽统一读取最终 $M_{t+s}$。零阶 Kalman 更新 M/P，水平—趋势 Kalman 更新 M/V/P；固定增益对应臂不维护 P。

同一轮两个槽的输入向量为 $[M_t,M_t]$，位置和树上下文可以不同，输出不必相同。填槽不推进 token 时间，不更新 M/V/P，不额外加 Q；不把两槽写成 M、M+V，也不写成 M+V、M+2V。旧前向已经产生的 logits、候选和 hidden 不被新 M 改写，沿用 ESP 的复用与后续验证流程。

calibration 与 warm-up 的整体分工保持。Q/R/P0 的具体估计器、损失与数值本轮暂不选定，已有拟合建议只作为后续候选；Q/R 在线更新继续后置。本次是算法合同说明，不代表新四臂已实现或完成校准。

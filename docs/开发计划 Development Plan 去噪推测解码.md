# 三、下一轮优先级与验收
1. **已有Kalman/EMA正确性准入**：按唯一研究计划P0列状态/观测、更新式、时间与owner/bonus对齐、冻结/reset和非有限值边界；复用现有镜像层加入必要的独立CUDA参考。先验证疑点，确认错误再修，不改输入或阈值求绿，不因旧实现名称宣称最优性。
2. **高价值Run与方案收束**：对齐原件、配置、模型/输入、实际设备、完整/partial终态和质量/收益/时长；新收束摘要只引用旧身份。来源缺失严格拒绝，不用当前helper或相近字节补签。成功项不重跑；负研究结果和执行失败分开。
3. **仅修直接阻塞研究结案的工程缺口**：报告/计数/来源、配置与启动、CUDA设备传播和状态恢复按具体消费者处理。需要真实模型诊断先按研究计划最小预算；未定效益比较的单位/预算先在唯一计划明确，不派发旧72、范数/配对长矩阵。
4. **低价值Study与冗余清理**：当前已完成队列和归档职责整理；进一步物理删除/归并前核消费者、固定source lock与取证依赖，保第三方字节与原始数据，不以清理名义删除未知来源。
5. 其余父包、旧声明、测试level/target/cost、Python3.10策略及日志容量问题仍是工程待办，按对研究主线的影响选择，不挤占上述核验/结案。测试通过只证明对应合同，不等于算法有效或远端CI通过。
